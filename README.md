# μT-Kernel 3.0向け エッジAI（Edge Impulse）実装用の統合ミドルウェアライブラリ

本プロジェクトは、世界的なエッジAI開発プラットフォーム「**Edge Impulse**」の推論SDKをリアルタイムOS「**μT-Kernel 3.0**」に完全移植・適合させ、画像、音声、センサーデータの取得から推論までをシームレスに行うための **エッジAI統合ミドルウェアライブラリ（TRON-EI）** です。

TRONプログラミングコンテスト2026の **「RTOSミドルウェア部門」** の開発プロジェクトです。

## 1. ミドルウェア概要と開発の背景

エッジAIモデルをリアルタイムOS（RTOS）上で動作させる際、ハードウェア依存コードの抽象化や、OS APIのポーティング（時間管理、メモリ管理、スレッド設計）が大きな障壁となります。

本ミドルウェアは、μT-Kernel 3.0 の上で Edge Impulse C++ SDK を快適に走らせるための **移植ブリッジ（ポーティングレイヤー）** を提供し、さらにマイク、加速度センサー、NPUドライバ、2D GPU描画などの低レベルデバイスドライバスタックを統合しました。これにより、アプリケーション開発者は複雑なハードウェアやOS APIのバインドコードを記述することなく、高度なマルチセンサーAI認識システムを即座に構築できます。

## 2. アーキテクチャと機能

本ミドルウェアは、アプリケーション層に対して以下の抽象化された機能を提供します。

### 1. Edge Impulse ポーティングレイヤー (OSブリッジ)
Edge Impulse が要求する以下の時間・メモリ・同期処理を、μT-Kernel 3.0 のネイティブAPIにポーティングしています。
* **ミリ秒・マイクロ秒タイマー**: μT-Kernelのシステムタイマー（`tk_get_tim`）および DWT（Data Watchpoint and Trace）サイクルカウンタをラップし、マイクロ秒レベルの正確な実行時間計測とタイムスタンプを提供。
* **動的メモリ管理**: μT-Kernelのメモリプール管理、またはスレッドセーフな `malloc`/`free` マッピングの定義。
* **シリアルデバッグ統合**: T-Monitor の `tm_printf`/`tm_putstring` によるシリアルコンソールロギングの統合。

### 2. 非同期センサーサンプリング＆推論パイプライン（プロデューサー・コンシューマー）
データの取りこぼしが許されない高精度なデータ収集と、重いAI推論・描画を非同期かつ安全に並行処理するためのマルチタスク用ミドルウェアフレームワークを提供します。

![センサー並列構成図](img/sensor_parallel_architecture.png)

* **データ収集・推論タスク (`task_2` / 優先度9〜10)**: 
  デバイスから一定周期（マイク: 16kHz/32kHz、Gセンサー: 62.5Hz/104Hz）でデータをサンプリングしてバッファへ蓄積し、バックグラウンドで推論をキックします。
* **液晶描画タスク (`task_1` / 優先度10)**: 
  Vblank 垂直同期（60Hz）で起床し、データ履歴バッファからオシロスコープ波形（Dave2D）を描画し、推論結果を液晶画面にレンダリングします。
* **アトミックバッファ保護**: 
  タスク間のデータ競合（Race Condition）を防ぐため、μT-Kernelのディスパッチ一時禁止API（`tk_dis_dsp` / `tk_ena_dsp`）を制御するアトミックデータ更新マクロを実装しています。これにより、音声データや加速度波形データが読み込み中に書き換えられて破損するのを完全に防止します。

## 4. ミドルウェアとしての優位性とアピールポイント

### 1. 100%音飛びのないデジタルオーディオ・ダウンサンプリング処理
マイク音声キーワード検出（`tron_pdm_detect`）において、PDMマイクからの 32kHz 音声データを DMA を介して受信し、DMA完了コールバック割り込みハンドラ内で瞬時に 16kHz へのダウンサンプリングを施します。
AI推論がバックグラウンドのNPU上で超高速（数ms〜数十ms）に処理されるため、高負荷な音声処理時にも割り込み処理に遅延（ジッタ）が生じず、マイク入力を1フレームも落とさず維持できるロバストなストリーム制御を実現しました。

![CPU vs NPU AI推論速度比較](img/cpu_vs_npu_comparison.png)

### 2. ソフトウェアI2C (Bit-Banging) および物理ポート自動検出 (Auto-Detect)
MPU-6050 加速度センサーを用いたプロジェクトにおいて、物理的なI2Cハードウェア端子が限られている場合でも動作するよう、GPIOピン制御によるソフトウェアI2Cドライバをミドルウェア層に実装。
マイコン上の異なる4対の接続ポート（ArduinoヘッダやPMODポート）の WHO_AM_I レジスタを走査する**自動ポート検出ロジック**を備えており、物理接続を自動検知して安定してセンサーを初期化できます。

### 3. 高精度スリープパターンによる 104Hz 等間隔サンプリング
加速度オシログラフ（`tron_i2c_d2_test`）において、RTOS上のタスク遅延関数（`tk_dly_tsk`）のみでは、1ms単位の量子化ジッタにより正確な 104Hz（平均9.615ms周期）のデータ収集が困難でした。
本ミドルウェアでは、**13サイクルに1回スリープ周期パターンを微調整するディレイ補正アルゴリズム**をタスク制御に組み込み、ジッタを最小限に抑えた極めて高精度な等間隔サンプリングを実現しました。

### 4. 2D GPU (Dave2D) を用いた高速ベクター波形描画エンジン
オシロスコープ波形（音声: 1024点、加速度: 307点）を高速描画するため、Dave2Dエンジンのライン描画パイプラインをラッピング。
画面全体の消去とベクター線のプロットを数ミリ秒以内で実行し、CPUフォント文字描画と組み合わせることで、**描画ちらつき（表示乱れ）を完全に防止**する高速グラフィックスAPIを提供しています。

## 5. 動作確認方法と開発環境
* **統合開発環境**: e2 studio (Renesas) / FSP v6.5.0
* **リアルタイムOS**: μT-Kernel 3.0
* **検証ボード**: Renesas EK-RA8P1
* **ビルド方法**: 各プログラムフォルダ内の `build.bat` を実行、または e2 studio 上でプロジェクトをロードしてコンパイルします。
* **提出オブジェクト**: 本ミドルウェアライブラリのソースコード一式、および各動作を確認できるサンプルアプリケーションプログラム、各プログラムのシリアルコンソール動作ログ例。
